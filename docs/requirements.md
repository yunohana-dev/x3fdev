# 要件

用語は `README.md` の定義に従う。

## 目的

Sigma の X3F を、ユーザーの好みに合った色調で自動的に現像し、JPEG として書き出す。

## 背景

- ユーザーは DP2（無印）、SD1 Merrill、dp0 Quattro の X3F を保有している
- 撮影枚数は dp0 Quattro ≧ DP2 ≧ SD1 Merrill の順に多い
- 好みの手本となる現像済み画像（教師データ）はない。ユーザー自身も「これが良い」と言い切れる現像結果を持っていない
- そのため、好みは比較評価から学習する必要がある

## 機能要件

### F1 デコード
- X3F を linear RGB の画像に変換できること
- 機種は X3F のメタデータから自動で判定すること。`--camera` で上書きできること。未知の機種はエラーにすること
- デコーダが使えない機種や品質が不十分な機種に備え、外部で作成した linear TIFF（SPP の 16bit TIFF 出力など）も入力として受け付けられる構造にすること

### F2 キャリブレーション
- X3F と、それを SPP の標準設定で書き出した TIFF の組から、機種ごとのカメラプロファイルを作成できること
- 作成時に、基準との色差（ΔE2000）を表示すること

### F3 チューニング
- 入力ディレクトリから評価用の画像を抽出し、ローカルの Web UI でペア比較を行えること
- 評価は逐次保存し、中断と再開ができること
- 評価ログからスタイルを学習し、プロファイルを更新できること
- 評価の一貫性（同じ組み合わせへの回答の一致率）と、学習の収束度を確認できること
- 参照画像の色調の統計から、スタイルの初期値を作れること（参照画像による初期化）

### F4 現像
- プロファイルと X3F から画像ごとのパラメータを決め、JPEG を書き出せること
- 複数ファイルとディレクトリを入力にとれ、並列に処理できること
- `--save-sidecar` 指定時、その写真の再現に必要な現像パラメータ一式をサイドカーファイルとして X3F の隣に保存すること
- サイドカーファイルには、プロファイルの値を参照ではなく実値で含めること（プロファイルが失われても再現できるようにするため）
- `--from-sidecar` 指定時、サイドカーファイルの値で再現すること。既定ではプロファイルから新規に生成すること
- 出力は sRGB、JPEG、リサイズなし

### F5 ジオタグ
- GPX ログと JPEG の EXIF の撮影日時から撮影位置を求め、JPEG に書き込めること
- タイムゾーン、カメラの時計のずれ、許容する時間差を指定できること
- 現像機能の完成後に着手する

## 非機能要件

- **元データの保護**: X3F に書き込まない
- **自己完結**: ツールの状態はすべてプロジェクトルートの中に置く。プロジェクトルートは、カレントディレクトリから上へ探索して特定する
- **再現性**: サイドカーファイルと同じバージョンのパイプラインがあれば、同じ JPEG（画素値の差が量子化誤差以内）を再現できる
- **管理**: プロファイルと評価ログは git で管理する。キャッシュと中間成果物は `tmp/` に置き、管理対象外とする
- **応答性**: チューニング中、候補画像 2 枚の表示まで 1 秒以内（キャッシュ済みの場合）
- **実行環境**: WSL2 上で CPU のみ

## 対象外

- X3F 以外の RAW（Sigma fp などが出力する DNG を含む）
- X3F へのパラメータの書き込み（SPP 互換の設定保存）
- 手動で現像パラメータを細かく編集する GUI
- GPU による高速化
- SD1 Merrill のレンズごとの色シェーディング補正（初期スコープ外。必要になれば追加する）
